# Head 0.0.2

仅发布 Head，Node 仍为 0.0.1；不自动更新线上容器或移动 latest。

## 修复

- 物理默认出口与 IPv6 隧道（例如 LA1 的 `ipv6net`）并存时，跳过隧道并选择物理出口，不再整体拒绝部署。只有隧道或没有可识别 device-backed 默认出口时仍拒绝，不回退到统计所有网卡。
- 将部署失败细分为网卡探测、已有非受管 Node、Compose 配置、镜像拉取及容器启动错误，仍不暴露原始命令或凭据。
- 保留旧部署保护：HK/MY 的 `~/enb-test` 不允许直接覆盖，不会自动迁移代理或删除旧数据。

## 验证与兼容

- Head 全仓测试通过（跳过四项外网 GeoIP 测试）、相关竞态测试、全仓 vet、更新器 17 项测试通过。
- 修复后的网卡脚本在 LA1/HK/MY 只读验证均选择 `eth0`；未重建远端 Node。
- 镜像启动、安装门禁、嵌入前端、匿名拒绝、EasyTier CLI 检查通过。
- 隔离真实 Compose 使用已初始化的 Head 0.0.1，验证宿主机更新器成功切换到 0.0.2、版本/hash/SQLite 就绪及安装状态保留；注入目标就绪失败后恢复旧镜像和停机数据快照。测试仅将 registry pull 替换为已验证的本地构建镜像，其余事务使用真实 Docker；发布时另行核对远端 manifest digest。
- 允许来源仅 Head `0.0.1`，平台 `linux/amd64`，需要人工接入独立宿主机 updater 及受支持的本地 SQLite、`/app/data` 单 bind 布局。浏览器到宿主机完整更新链路、复杂代理业务和旧 `0.2.1-enb-*` 迁移未验收。
