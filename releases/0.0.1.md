# ENB 0.0.1

Head 与 Node 首个独立数字版本，平台为 `linux/amd64`，源码提交为 `ba91ca658d10ada186b516c90110d1cf3bbd4b8a`。

- Head：ENB 动态 Git 发布目录、独立宿主机更新器接口、Node 独立升级页及权限管理；左侧栏为仪表板 → 虚拟内网 → 服务器，左下角 GitHub 指向 ENB。
- Node：独立远程权限参数；通过 Docker 固定版本发布，禁用容器内上游二进制自动更新。
- 标签：`docker.io/nodokaqwq/enb:head-v0.0.1`、`docker.io/nodokaqwq/enb:node-v0.0.1`。精确 digest 见同目录 stable JSON；不移动 latest。

## 验证范围

- 前端 763 项测试及生产构建；Head 全仓测试（跳过四项外网 GeoIP 查询）、相关竞态测试、全仓 vet；Agent cmd/server/terminal/update 测试。
- Python 宿主机更新器 17 项测试，发布目录校验。
- 两个真实镜像启动、平台/OCI 版本与提交标签；Node 权限参数和非法策略拒绝；Head 安装门禁、匿名访问拒绝、嵌入前端、EasyTier CLI。
- 隔离真实 Compose 下完成 Head 初始化，核对版本/hash/本地 SQLite 就绪；验证同版本升级拒绝，以及更新器停机数据快照恢复、旧镜像重建和安装状态保留。

## 安装基线，不开放旧版本迁移

本次仅发布镜像，不更新线上容器。首次安装须人工部署；旧 `0.2.1-enb-*` 未完成逐版本迁移验收，不列入允许来源。清单中的 `from_versions: ["0.0.1"]` 仅作为首版基线占位，同版本更新被后端拒绝，**不构成任何可执行升级路径**。

Node 真实 SSH→Agent 更新闭环、代理业务连通性、旧版本数据迁移及浏览器→宿主机完整升级闭环未验收，不宣称通过；后续开放升级路径前必须单独验证并递增版本。Head 宿主机更新器须人工安装并接入受支持的本地 SQLite/bind 数据布局。
