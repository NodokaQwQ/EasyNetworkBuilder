# 按服务器管理回程监测（未发布源码）

- 新建任务只选择一台服务器，在任务中添加 1–64 个目标；每个目标填写 IP/域名、地址类型、运营商、预期线路及可选地区。
- 列表、筛选和分页按服务器聚合，命中一个目标时仍展示该服务器的所有目标，避免编辑时误删未显示的目标。
- 每个目标保留独立探测 ID、线路状态、通知与历史。旧任务无需重建，自动按服务器聚合；首次整体保存会将公共间隔、启停与通知配置统一到本次表单设置。
- 每个目标自动创建独立 ICMP 延迟/丢包监测。`ping_interval=0`（页面留空）跟随回程间隔；显式设置允许 1 秒至回程间隔，不能更慢。延迟/丢包告警沿用已有默认通知设置，不会无条件开启通知。
- 关联监测由回程目标管理：修改间隔、启停、删除联动，不允许在延迟监测页直接改写/删除。手工监测不接管、不删除；原先显式指定的疑似被墙辅助监测继续保留。
- 修改目标会重置该目标的线路基线，并为新目标创建新的延迟序列，避免混用历史；旧回程事件保留。删除目标会删除其回程历史，并排队清理自动延迟监测的指标。
- 模板仍作为单目标预设：可在服务器任务中逐个添加多个模板，也可继续批量应用到服务器；创建的目标会归入对应服务器并自动关联延迟监测。
- 服务器整体保存通过事务执行，并检查打开表单时的目标 ID 集合，拒绝覆盖并发新增/删除的目标；同一 IP/域名与地址类型不能重复配置。
- 疑似被墙判定仍按服务器、地址类型及不同运营商聚合；多个同运营商目标不算多个运营商。

## 接口

- `POST /api/admin/return-route/servers/query`：筛选参数与旧任务查询一致，返回按服务器分页的 `servers`，每项包含完整 `tasks/statuses/reachability/probing_task_ids`。
- `POST /api/admin/return-route/servers/save`：公共配置、`client`、`targets[]` 与 `existing_target_ids[]`。新增服务器任务使用空 existing IDs；更新时传入打开编辑时已有的全部目标 ID。目标保留 `id` 表示更新，无 ID 表示添加，省略旧目标表示删除。
- 原单目标接口、Node 探测协议和事件深链保持兼容。本次不要求重装 Node。

## 限制

现有 Node 的 ICMP 域名延迟探测使用 DNS 返回的首个地址；回程探测则使用所选 IPv4/IPv6。双栈域名不保证两者选择相同地址/同一地址族，如需严格对照应填写具体 IP。本次仅修改 Head 与管理前端，未改 Node 协议。
